## Что делает проект

«МедСвязь 24/7» — веб-инструмент оценки **потенциальной автомобильной доступности выбранных медицинских площадок**. На карте можно сравнить регионы и отдельные поселения, изучить базовые маршруты до медицинских учреждений, рассчитать изменения индекса при сценариях и оценить социальный охват. Экономический модуль рассчитывает эффективность *только при явных финансовых допущениях*. Данные по больницам и маршрутам имеют ограничения — см. методику.

**Дорожные гипотезы (обновление):** сайт снова предлагает **новые дорожные связки**, но только короткие (примерно 0,15–1 км) между уже существующими дорожными узлами около населённых пунктов. Каждый кандидат рассчитан на настоящем графе: показывается эскиз отсутствующей связи и изменение маршрутов/МИЭД. Важно: это **аналитические, НЕ подтверждённые по безопасности и землеотводу** гипотезы — автоматический фильтр по OSM не заменяет карты военных зон, кадастр, проверку водных объектов и инженерную экспертизу. Настоящие предварительно документированные коридоры по-прежнему можно добавить отдельно в `data/planning/approved-road-corridors.json`. [Алгоритм, ограничения и воспроизведение](docs/NEW_ROAD_SCENARIOS.md).

### Доработка 12.11: ML, индекс в интерфейсе и качество медицинских источников

- На странице региона **МИЭД v6.1 вынесен в главный блок**, рядом с охватом, P90, долей пунктов в пределах порога и типом источников больниц. **Карта сразу под управлением сценариями**; прежние панели проектов и расширенной аналитики ниже.
- Проведён **поштучный аудит больничных площадок**: 21 отобрана по официальным источникам в трёх пилотах; ещё **925 OSM-объектов в 30 регионах не имеют независимой проверки профиля**. Для каждого подготовлен список сверки с официальным реестром (`public/downloads/medical-facilities-needing-verification.csv`); эти объекты *не* обозначены официально подтверждёнными.
- Исправлена ошибка независимой SciPy-проверки параллельных дорожных дуг. [Новые числа и регрессионные тесты](docs/VALIDATION_ROADS_v5_1.md).

### Главные возможности

- Собственный **МИЭД v6.1**: 75,2% веса распределяется между включёнными поселениями поровну и 24,8% — по населению; оценка пункта складывается из ближайшей больницы (85%), резервной (10%) и модельной устойчивости к трём перекрытиям (5%). Комфортная зона 0–15 мин, после 60 мин спад доступности ускорен, `τ=40` мин по умолчанию. Полнота перечня больниц и вероятность перекрытий не подтверждены.
- 33 региональных набора на реальных исходных геоданных и 52 **отдельно отмеченные синтетические** модели; ещё 4 территории без расчётов. Модельные времена не равны измеренным.
- Базовые маршруты, многовариантное сравнение «до/после», изменение индекса и времени, количество затронутых поселений и их жителей.
- Моделируются **ускорение существующей дороги** и **новая короткая модельная дорожная связь**, когда она меняет маршрут и индекс. Новая связь — не разрешённая к строительству трасса: требуется внешняя проверка территории; дополнительная медплощадка также остаётся гипотезой до сверки реестра.
- Экономика: сценарный CAPEX/OPEX, стоимость единицы прироста индекса, NPV и срок окупаемости при подтверждённых денежных данных. Нет данных — нет доказанной окупаемости.
- Источники, CSV/JSON выгрузки, методика и тесты воспроизводимости.

## 🛣️ Новая дорога: как читать результат

- Сценарий **«Предложить новую дорогу»** проверяет короткие новые связи между дорожными узлами и выбирает вариант с положительным пересчитанным приростом МИЭД.
- На карте **розовый пунктир — модельный эскиз**, а не безопасная трасса, согласованный проект или разрешение на строительство. Региональный режим автоматически показывает поселение, где новый маршрут действительно отличается от базового.
- **Не планируйте строительство по карте сайта.** Отдельно нужны официальные сведения о военных ограничениях, воде, ООПТ, земельных правах, профиле дороги, а также технико-экономическое обоснование. Если данных не хватает, статус проекта — «требует проверки».
- Для воспроизведения кандидатов см. `scripts/generate_road_candidates.py` и `data/planning/algorithmic-road-candidates.json`.

## Как запустить сайт через Docker (Windows / PowerShell)

**Важно:** Full содержит все дорожные графы, Lite — только графы трёх исходных пилотных регионов (Калининградской, Ивановской и Псковской областей). Обе версии содержат обязательные данные для запуска. Для пересчёта маршрутов в остальных 30 регионах нужен Full. Должен работать Docker Desktop.

1. Распакуйте полный проект в отдельную папку `medsvyaz24`.
2. Откройте PowerShell в папке с файлом `docker-compose.yml`.
3. Выполните команды:

```powershell
$env:MEDSVYAZ_PORT="5181"
docker compose -p medsvyaz24-final up --build -d
```

4. Откройте [http://localhost:5181](http://localhost:5181) или раздел сценариев [http://localhost:5181/scenarios?region=pskov](http://localhost:5181/scenarios?region=pskov).
5. Диагностика: `docker compose -p medsvyaz24-final ps`, затем `docker compose -p medsvyaz24-final logs --tail=80 web`.

**Отдельная копия не заменяет старый контейнер**, если использовать другое имя проекта и свободный порт `5181`. Если порт занят, выберите `5182`.

**Запуск без Docker** (Node.js 22.13+):

```bash
npm ci
npm run build
npm start
```

Сайт по умолчанию на `http://localhost:5180`. Для проверки можно выполнить `npm test`, `npm run verify`, `python3 scripts/verify_v61.py`. Python не нужен только для обычного запуска. Полные скрипты подготовки геоданных — для воспроизводимого пересчёта.

## Методика в двух строках

```text
A(t) = 1                                    если 0 ≤ t ≤ 15 мин
A(t) = 2^(-(t-15)/(τ-15))                   если 15 < t ≤ 60 мин
A(t) = 2^(-(45+2(t-60))/(τ-15))            если t > 60 мин, τ=40
S_i = 0.85 A(t_i,1) + 0.10 A(t_i,2) + 0.05 U_i
U_i = min_e A(t_i,nearest after closure of e)  по 3 выбранным перекрытиям
МИЭД = 100 × Σ_i (0.752/N + 0.248 p_i/P) × S_i
```

В реальных данных учитываются только *включённые и проверенные в рамках модели* поселения, отсутствие пути из-за неполной сети не приравнивается к достоверной изоляции. При разных наборах медицинских площадок результаты нужно сравнивать с оговорками. Для расширения до общественного транспорта нужны расписания и другие проверенные данные.

## Как разместить проект на GitHub без проблем с размером

- **Не загружайте `node_modules/`, `dist/`, временные PDF-рендеры и первичные большие OSM-файлы.** Git должен хранить исходники и документы.
- Исторический репозиторий содержит несколько частей; перед публикацией новой версии лучше создать **чистую ветку/релиз** либо отдельный лёгкий репозиторий, а не пытаться пушить гигабайты прежней истории.
- Установите правила из [`docs/GITHUB_PUBLISH_FINAL.md`](docs/GITHUB_PUBLISH_FINAL.md). Большие графы и данные храните в Google Drive с контрольными суммами и ссылкой из этого README.
- Ограничение GitHub для отдельного файла — 100 МиБ; для больших файлов используйте Release assets, Git LFS (при наличии квоты) или Drive. Не забывайте ODbL и атрибуцию OSM.

## Честные ограничения

В проекте нет единого подтверждённого общероссийского индекса, действующего мультимодального расчёта для всех регионов, проверенных трасс новых дорог или смет строительства. Нельзя выдавать синтетические регионы за измеренные, OSM-тег «больница» за официальную возможность получить выбранную помощь, а индекс за время прибытия скорой помощи. Перед реальной инвестицией необходимы профильные обследования и согласования.
