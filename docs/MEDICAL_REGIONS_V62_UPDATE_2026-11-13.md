# МедСвязь 24/7 — региональные медицинские справочники и МИЭД 55/35/10

**Статус:** рабочий патч; официальный аудит всех площадок не завершён. В GitHub ничего не изменяется.

## Какие данные теперь есть

- **33 региона с реальными данными:** сохранены 963 картографических записи больниц из оригинального проекта. Координаты из OSM или ранее сверенных официальных адресов; клиническая лицензия и круглосуточность в 30 расширенных регионах **не подтверждены**.
- **Калининградская область:** в каталоге отображаются дополнительные взрослые и детские поликлиники и частные клиники из OSM-снимка, вместе с больничными площадками базового расчёта. Неясные, родильные, стоматологические, амбулаторные объекты не показываются.
- **30 других реальных регионов:** справочник координат больниц готов; поликлиники требуют обновления OSM через приведённую ниже команду. Нули до обновления означают **отсутствие данных в поставленном архиве**, а не отсутствие поликлиник в реальности.
- **52 синтетические региональные модели:** дополнительные взрослые, детские и условные частные клиники распределены воспроизводимо по размерам населённых пунктов; все помечены синтетическими. Это не фактическая сеть оказания помощи.

Папка `public/data/medical-catalogs/` содержит по одному JSON на каждый регион. Записи включают название, координаты, тип, происхождение, OSM-ссылку, `officiallyVerified`, `inpatientVerified`, `roadNodeId` (если объект привязан к графу), `snapDistanceMeters`.

## Как получить максимально полные картографические координаты поликлиник для остальных регионов

Из корневой папки проекта (Mac; интернет обязателен):

```bash
python3 -m pip install --user brotli scipy numpy
python3 scripts/build_regional_medical_catalogs.py --refresh-osm
python3 scripts/build_kaliningrad_rankings_v62.py
docker compose up --build -d
```

Загрузчик обращается **только для чтения** к опубликованному OSM-геонабору и сохраняет исходные 2-градусные фрагменты в `data/medical-osm-cache/`. Территория определяется по многоугольникам границ `data/processed/geometries.json`; объекты вне границ исключаются. После загрузки строятся 85 локальных JSON-каталогов. Повторные запуски используют кэш. При неполной загрузке уже найденные точки сохраняются; в терминале сообщаются отсутствующие фрагменты.

Источник: [OpenStreetMap / ODbL](https://www.openstreetmap.org/copyright); OSM-выгрузка: `https://github.com/01shane89-jpg/AXIOM-APSAP/tree/main/data/medfac/t`.

**Что не может сделать OSM:** подтвердить, что больница принимает на круглосуточный стационар, какая у неё лицензия, что поликлиника оказывает бесплатную помощь по ОМС и что точка не закрылась. Официальный ФРМО содержит такие сведения, но его публичный список без адресного сопоставления нельзя автоматически считать полной картой филиалов: https://minzdrav.gov.ru/special/ministry/web-site/informatsionnye-sistemy-minzdrava-rossii/katalog-podsistem-egisz/federalnyy-reestr-meditsinskih-organizatsiy. Для принятия инвестиционного решения необходима ручная проверка по ФРМО, ТФОМС и официальным сайтам.

## Индекс

**Исторический МИЭД v6.1** (85% ближайший стационар, 10% резервный, 5% стресс-тест) **сохранён** для воспроизводимости прежних результатов. Его нельзя сравнивать напрямую по абсолютной величине с новой формулой.

Для регионов с привязанными к дорожному графу поликлиниками включается экспериментальный **МИЭД v6.2**:

\[
S_i = 0{,}55 A(t_{hospital,i}) + 0{,}35 A(t_{polyclinic,i}) + 0{,}10 A(t_{stress,i})
\]

\[
I = 100 \sum_{i=1}^N \left(\frac{0{,}752}{N}+\frac{0{,}248p_i}{\sum_j p_j}\right)S_i.
\]

Функция `A(t)` прежняя: до 15 минут максимальная доступность, после 15 — экспоненциальное снижение, после 60 минут — усиленное снижение. Параметр τ управляет моментом половинной доступности, типично 40 мин.

- `t_hospital` — время до ближайшей *выбранной в модели* больничной площадки.
- `t_polyclinic` — время до ближайшего картографически идентифицированного **публичного/предположительно публичного** амбулаторного учреждения. Это **не доказательство** бесплатного лечения или наличия врача нужного профиля.
- `t_stress` — модельное время до ближайшей больницы при выбранных перекрытиях; не вероятность перекрытия.
- Возрастные группы **не входят в МИЭД**; только в рейтинг проектов.

Если данные о поликлиниках пока отсутствуют, сайт сохраняет исторический v6.1 вместо того, чтобы занулять 35% и выдавать отсутствие данных за отсутствие медпомощи. На таких страницах новые и старые результаты не следует ранжировать вместе. После успешного импорта поликлиник и перезапуска сервер использует v6.2 для региона.

Отдельно выводятся `P90 до больницы` и `P90 до поликлиники`. Статистики относятся к известным достижимым поселениям, а не к каждому жителю.

## Калининград: обновлённый рейтинг

В `scripts/build_kaliningrad_rankings_v62.py` единая формула 55/35/10 используется для исходной сети и каждого последовательного добавления новых объектов. В портфелях три объекта добавляются **совместно**. При расчёте учитываются существующие больницы и поликлиники из текущих данных. Из отбора исключены населённые пункты Правдинск, Янтарный и Полесск, где есть сведения о действующей мединфраструктуре, отсутствовавшей в старой расчётной базе. Это **предохранитель от очевидных ложных рекомендаций**, а не доказательство полноты справочника.

Рейтинг для государственных объектов задаётся в коде формулой с нормировкой по лучшему кандидату на шаге: 45% прирост индекса, 25% возрастно-взвешенный охват населения, 20% выраженность локального недостатка медучреждений, 10% близость к дорожному узлу.

Рейтинг для частных: 35% прирост *условного* индекса (как при бесплатной поликлинике), 25% размер локального рынка, 20% удалённость от конкурентов, 15% возрастно-взвешенный охват, 5% близость к дороге. Оценка коммерческой окупаемости не рассчитывается.

Кандидаты являются **предварительными транспортными гипотезами**. Не учтены реальное зонирование, земельные участки, мощности стационаров, занятость коек, списки отделений, потребность в кадрах, стоимость строительства и лицензирование.
