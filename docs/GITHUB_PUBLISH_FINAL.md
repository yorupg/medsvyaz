# Как загрузить МедСвязь 24/7 на GitHub без ошибок из-за большого объёма

## Рекомендуемый способ: код и документы — GitHub, большие графы — Google Drive

В полном проекте `data/processed` содержит большие сжатые географические файлы, а `data/raw` — историю первичных загрузок. **Не загружать `node_modules` и исходные OSM PBF в Git!** На GitHub разместить лёгкий проект, в Drive хранить полную версию данных. В README первой строкой дана ссылка на Drive.

### Шаг 1 — подготовка

1. Распакуйте **полный** архив `MedSvyaz24_FULL_FINAL.zip` (для запуска через Docker).
2. Для репозитория возьмите **облегчённый** архив `MedSvyaz24_GitHub_Light.zip` — в нём код, документация, расчётные результаты, но нет больших графов и первичных данных.
3. Убедитесь, что `README.md` лежит **в корне GitHub-репозитория**, а не только внутри `medsvyaz-part-3/`.
4. Откройте папку с файлами `README.md`, `package.json`, `docker-compose.yml` в VS Code.

### Шаг 2 — проще всего: новый пустой репозиторий

Если у прежнего `yorupg/medsvyaz` уже очень тяжёлая история из трёх частей, безопаснее создать новый пустой репозиторий `medsvyaz-final` и показать ссылку на него. При необходимости потом вернуть название/ссылку в основной репозиторий. GitHub Desktop также подойдёт.

```powershell
git init
git add .
git commit -m "Final A2 project, documentation and safe road-scenario gating"
git branch -M main
git remote add origin https://github.com/yorupg/medsvyaz-final.git
git push -u origin main
```

**Прежде чем выполнить `remote add`, создайте на GitHub пустой `medsvyaz-final` без автоматического README** и при необходимости замените URL на настоящий. Не выполняйте `git init` внутри существующего клона с другой историей без понимания последствий.

### Шаг 3 — если обязательно тот же `yorupg/medsvyaz`

1. Проще всего в веб-интерфейсе открыть `https://github.com/yorupg/medsvyaz`, нажать `Add file → Create new file`, указать `README.md` и вставить содержимое нашего `README.md` — тогда ссылка на Google Drive сразу будет на главной странице, даже если остальные файлы ещё не обновились.
2. Для кода использовать новую ветку, не перезаписывая `main` с тремя старыми частями; создать Pull Request. Поднимать большие архивы через веб-интерфейс GitHub не нужно.
3. Если старый репозиторий уже занимает много места, `git push` может быть медленным из-за истории — публикуйте лёгкую версию отдельно или переносите очищенную историю только с согласия команды. Не используйте `git push --force` на командной ветке без согласования.

### Шаг 4 — обязательно проверьте

- Главная страница GitHub **сразу** показывает ссылку Google Drive.
- На GitHub открывается файл `jury_materials/00_Презентация_интерфейса_для_жюри.pdf`.
- В README написано, что полный Docker-запуск требует восстановить `data/processed` и `data/derived` из Drive.
- `README.md` и `jury_materials` доступны преподавателям без прав авторизации.
- Содержимое Google Drive расшарено «Все, у кого есть ссылка → Читатель» (проверяет владелец папки).

## Команды для запуска из полного архива

```powershell
$env:MEDSVYAZ_PORT="5181"
docker compose -p medsvyaz24-final up --build -d
```

Порт 5181 не заменяет контейнер v5 на 5180. Для проблем: `docker compose -p medsvyaz24-final logs --tail=80 web`.
