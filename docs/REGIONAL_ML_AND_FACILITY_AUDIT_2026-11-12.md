# Расширение МИЭД: ML-поиск аномалий и проверка медицинских данных

**Дата:** 12 ноября 2026 · **цель:** рабочий прототип А2; результаты не предназначены для медицинской маршрутизации и проектирования дорог.

## 1. Реализовано: ML для всех 33 реальных регионов

- 3 исходных пилота и 30 регионов OSM/ВПН-2021.
- Для каждого региона отдельно рассчитано отставание `E[балл МИЭД | география] − балл МИЭД`.
- Признаки: расстояние по прямой до 1-й и 2-й ближайших выбранных больничных площадок, число площадок в 15 и 30 км. Дорожное время в признаки не включено; это целевая величина через МИЭД.
- Для 32 регионов используется стандартизация географических признаков без меток и `cKDTree` для поиска 20 ближайших соседей *в других муниципалитетах*. При проверке исходы текущего муниципалитета не входят в обучающую выборку. Это по-прежнему трансдуктивная стандартизация по признакам всей области, а не проверка переноса на совсем новую область.
- Калининград: сохранён ранее подготовленный отдельно проверенный прогноз с раздельной стандартизацией по муниципалитетам, а также сравнение с коэффициентом объезда.
- Каждый JSON содержит 10 наибольших положительных разрывов и MAE по исключённым муниципалитетам; CSV содержит все включённые поселения.
- Отрицательная оценка дорожной доступности относительно географических аналогов **не доказывает** плохое качество реальной дороги, отсутствие медпомощи или необходимость строительства.
- Отчёт привязан к **исходной сети, τ=40 мин, `timeScale=1`**; он скрывается при других параметрах/сценариях. Изменение набора больниц требует полного пересчёта ML.

Воспроизведение:

```bash
python3 -m pip install numpy scipy scikit-learn brotli
python3 scripts/train_regional_peers.py
python3 -m unittest discover -s scripts/tests -v
```

Отчёты: `data/derived/regional-ml-audit.json`, `public/downloads/<regionId>-peers.json` и `-peers.csv`.

## 2. Состояние подтверждения медицинских объектов

Все 33 реальные области используют ОSM-дорожный граф и поселения ВПН-2021. Но состав медицинских площадок **не одинаков по происхождению**:

| Наборы | Количество | Источники больниц | Можно ли считать профиль официально подтверждённым? |
|---|---:|---|---|
| Калининградская, Ивановская, Псковская | 3 региона, 21 площадка | Отдельный подбор с официальными документами, сверенный с координатами OSM | Подбор по официальным источникам; фактический приём/отделения всё равно не подтверждены |
| Остальные реальные регионы | 30 регионов, 925 OSM-объектов | Именованные `amenity=hospital` из архивных OSM/PBF | **Нет**; карта не является реестром медицинских учреждений |

В 925 OSM-объектах у 287 есть текстовый адрес; у остальных адрес в исходном наборе пуст. Это не означает, что сам медицинский объект не существует: **отсутствие данных** и **отрицательный результат проверки** разные вещи.

Переписные населённые пункты и дороги исходно собраны по единой методике, но региональные значения нельзя объявлять сопоставимыми по **официальному профилю больниц**, пока 30 наборов не сверены с реестрами.

Рабочий список `public/downloads/medical-facilities-needing-verification.csv` содержит для всех 925 объектов OSM-ID, название, координатную ссылку, имеющийся адрес и пустые поля для подтверждения. Незаполненные поля **не** заполняются автоматически по сходству названий. Сводка `public/downloads/medical-facility-coverage.json` отображается на каждой странице реального региона.

**Как довести эти 30 наборов до уровня пилотов**:
1. Получить актуальные реестры медорганизаций территориальных фондов ОМС или данные ФРМО для каждого региона. Для ФРМО требуются сведения не только о головной организации, но и о конкретной площадке/подразделении и адресе.
2. Выбрать **единый тип оказываемой помощи**, например стационарную помощь широкого профиля, а не произвольное название больницы.
3. Сопоставить учреждение и конкретный адрес из реестра с исходным OSM-объектом (нельзя считать совпадение по имени достаточным). Отдельно проверять переименования, филиалы, ошибочные точки и исключённые учреждения.
4. При добавлении/удалении подтверждённых площадок пересобрать соответствующий граф и пересчитать **МИЭД и все связанные ML-оценки, списки дорог и сценарии**. Старые региональные баллы не должны сохраняться.
5. Опубликовать источник, дату, долю подтверждённых площадок и ограничения сравнения.

В архиве **нет** региональных официальных реестров и исходных 30 OSM PBF (есть сжатые графы и ссылки/хеши источников), поэтому полную сверку 925 площадок нельзя выполнить воспроизводимо без получения дополнительных документов. Не следует подменять это добавлением ссылок на федеральный реестр без проверки отдельных адресов.

Для сверки используются официальные источники: Министерство здравоохранения РФ (система ФРМО): https://minzdrav.gov.ru/ministry/web-site/informatsionnye-sistemy-minzdrava-rossii/katalog-podsistem-egisz/federalnyy-reestr-meditsinskih-organizatsiy и опубликованные территориальными фондами реестры организаций ОМС.

## 3. Навигация и независимая проверка дорог

На странице региона первым расположен выделенный **МИЭД v5**, рядом — охват, P90, доля поездок в пределах τ и происхождение больниц. После выбора сценария карта выводится сразу под панелью управления; список предлагаемых дорожных проектов, ML-поиск, качество данных и остальные таблицы идут ниже.

В `scripts/verify_road_scenarios.py` параллельные дуги между двумя вершинами теперь объединяются по **минимальному** времени до построения CSR-матрицы. Старый вариант суммировал их и искажал независимый расчёт. Скрипт также сверяет исходные индексы с сохранёнными значениями TypeScript. Числа исправленного отчёта: `data/derived/road-scenarios-independent-v5-fixed.json`.

Выполнены офлайн-тесты `python3 -m unittest discover -s scripts/tests -v`. Полную сборку фронтенда, Docker и браузерные сценарии необходимо отдельно проверить в среде, где устанавливаются npm-пакеты.
